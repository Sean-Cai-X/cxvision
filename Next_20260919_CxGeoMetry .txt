# YOLOv8-Seg 旋转等变粗姿态模型与 CxGeoMetry 演化推进基线

> **目标**：先在现有 YOLOv8-Seg 训练/推理链中验证离散旋转等变特征和 Angular Extraction Head，证明其能够为 FastMatch 提供更稳定的粗姿态；验证通过后，只抽取可复用的群特征、角度分布和设备算子能力，接入 CxGeoMetry 的显式多尺度模型图。
> **定位**：G-CNN 是模型感知层的姿态升级，不替代 Normal Trace、FormFit、标定和最终量测判定。
> **原则**：先证明正确性和应用收益，再推广到 CxGeoMetry；不直接引入第二套模型 Runtime，不把 Python e2cnn/escnn 变成生产依赖。

---

# 0. 总体结论

这条路线可以推进，但需要先修正两个容易混淆的问题。

第一：

> **G-CNN 能让特征按照预定义的旋转群规律变化，但不等于模型天然获得无限精度的角度。**

离散 `C12/C24` 网络只能在离散群结构上保持等变；亚 Bin 角度需要通过圆周分布解码、插值或后续精修获得。像素栅格和任意角度采样仍会造成离散化误差，e2cnn 官方材料也明确指出连续旋转在像素网格上存在离散化伪差。

第二：

> **G-CNN 输出仍然只能作为粗姿态和搜索先验。**

最终流程保持：

```text
G-CNN Coarse Pose
        ↓
FastMatch 搜索初始化
        ↓
Normal Trace 真实图像边缘
        ↓
FormFit / Geometry Fit
        ↓
Calibration
        ↓
Predictive Geometry Gate
        ↓
正式量测 / 预测假设 / 人工审核
```

因此正确的两阶段路线是：

```text
阶段 A：
在 YOLOv8-Seg 中验证旋转等变模型与 Angular Head

阶段 B：
提取验证过的群表示、角度分布和设备算子
接入 CxGeoMetry 的显式模型图
```

CxGeoMetry 的既定方向仍然是把 FastMatch/CxTextInspect 的多尺度原型、明确 Route 和逐级候选转换为可版本化、可训练的显式模型体系，而不是把它变成另一个 YOLO。

---

# 1. 当前代码状态：哪些已经完成，哪些仍缺失

必须以当前代码为起点，避免重复安排已经落地的工作。

## 1.1 已经完成的部分

### 严格权重加载已改为两阶段

当前 `load_state_dict_strict()` 已经先完成 Key 和 Shape 检查，只有 `report.complete()` 通过后才统一复制权重，模型不会再因后续发现错误而处于部分加载状态。当前还存在独立的分类头迁移路径，允许目标类别变化时严格迁移公共特征并显式重新初始化分类输出。

因此此前的：

```text
修复 strict loader 原子性
```

不再是新工作的主任务，只需补固定负向测试和报告完整度。

### Task-Aligned Assignment 已经接入训练

当前 YOLOv8-Seg 训练路径已经构建所有尺度 Anchor 表，并调用 `TaskAlignedAssigner`，根据分类分数、IoU、GT 内部约束和 Top-K 选择正样本。

因此不能再把当前训练描述为：

```text
只有每层中心 Cell Smoke
```

更准确地说是：

```text
Task-Aligned Assignment 已接入
但当前返回合同和几何 Target 传播仍需要扩展
```

### Mask BCE + Dice 已经接入

当前正样本 Mask Loss 已经由：

```text
BCEWithLogits
+
Dice
```

构成，并可通过 `mask_dice_loss_weight` 配置。

因此本轮不再重复安排“增加基础 Dice Loss”。

### 几何 Target 已能读取和 Tensor 化

当前 Dataset Sample 已经能够读取：

```text
primitive_type
center_x
center_y
envelope_width
envelope_height
sin_angle
cos_angle
valid_mask
```

并在 Letterbox 后转换到统一输入坐标。

---

## 1.2 当前真正缺失的部分

### 没有旋转等变卷积

当前 `YoloV8SegmentImpl` 仍然完全由普通 `ConvModule`、C2f、SPPF、PAN/FPN 和普通分割 Head 构成；代码中没有 Group Conv、Steerable Conv、E(2) Field Type 或等变特征表示。

### 没有 Angular Extraction Head

当前 Head 只输出：

```text
box_logits
class_logits
mask_coefficients
prototypes
```

没有：

```text
orientation_logits
angle_distribution
angle_confidence
group_response
```

。

### 几何 Target 尚未进入模型输出和 Loss

当前几何 Target Tensor 已经构建，但在 `compute_losses()` 中主要用于统计：

```text
geometry_target_valid_fields
geometry_primitive_type_available
```

没有 Geometry Head，也没有真正计算角度、中心、尺寸或几何一致性损失。

### 当前 Geometry Target 是“每张图一组”，不是“每个实例一组”

`YoloV8SegDatasetSample` 当前保存多个：

```text
boxes
polygons
classes
```

但只保存一套：

```text
geometry_primitive_type
geometry_target_values[6]
geometry_target_valid[6]
```

这无法正确支持一张图中的多个实例拥有不同角度和几何参数。

这是实现 Angular Head 前必须优先修正的数据问题。

# 2. 技术路线选择

## 2.1 第一阶段采用离散旋转群 `C_N`

推荐顺序：

```text
C4
→ 单元测试和算子正确性

C12
→ 第一版工程验证

C24
→ C12 收益不足时再评估
```

含义：

```text
C4  = 90° 一个方向
C12 = 30° 一个方向
C24 = 15° 一个方向
```

`C4` 适合验证群通道循环移位是否完全正确，因为 `90°` 可通过像素网格上的 `rot90` 做近似无插值验证。

`C12/C24` 更适合工程角度覆盖，但任意 30°/15°旋转需要图像或卷积核插值，严格等变性会受到像素离散影响。

G-CNN 通过群卷积增加权重共享，并使特征在输入旋转时按照指定群作用变换，这是其理论价值。

## 2.2 暂不直接实施连续 E(2)-CNN

连续 E(2)-Steerable CNN 使用群表示和受约束的可转向卷积核，理论上可以表达连续旋转等变。

但当前项目是：

```text
Windows
C++
LibTorch Runtime
自有 C++ 网络结构
严格 state_dict 加载
```

而 e2cnn/escnn 主要是 Python PyTorch 扩展；旧 e2cnn 已被官方标记为逐步弃用并建议迁移到 escnn。

因此第一阶段建议：

```text
生产实现：
C++ / LibTorch 离散 C_N Group Conv

研究参考：
Python escnn / e2cnn

连续 E(2)：
第二阶段独立研究
```

禁止第一阶段直接把 Python e2cnn 作为 `libtorch_module_runtime.dll` 的生产依赖。

---

# 3. 推荐架构：先并行 Pose Branch，再考虑替换主干

用户提出“替换 P3/P4/P5 和 Neck 中的卷积”是长期方向，但不适合作为第一步。

原因是：

> 只替换中高层卷积，并不能自动让整个网络严格旋转等变。

如果 P1/P2 的普通 CNN 已经以不可控方式改变了旋转特征，那么后续 Group Conv 接收的并不是具有明确变换规律的 Field。

因此建议分两个版本。

---

## 3.1 V2A：并行 Equivariant Pose Tower

保留当前 `YoloV8SegmentImpl V1` 完全不变：

```text
V1 Backbone
→ V1 Neck
→ Box / Class / Mask / Proto
```

新增独立分支：

```text
RGB Image
→ Group Lift Conv
→ Group Stage P3
→ Group Stage P4
→ Group Stage P5
→ Angular Extraction Head
→ Coarse Pose
```

最终：

```text
Standard YOLOv8-Seg
→ Instance / Mask / BBox

Equivariant Pose Tower
→ Angle Distribution / Confidence
```

优点：

```text
不破坏原始权重兼容
不影响现有分割基线
方便做 A/B Test
方便单独冻结或删除
能独立证明等变特征是否有价值
```

这是第一版首选。

---

## 3.2 V2B：中高层 Group C2f / Group Neck

只有 V2A 验证通过后，才进一步：

```text
P3/P4/P5 C2f
→ Group C2f

Neck Fusion Conv
→ Group Conv

普通 Concat
→ Group-aware Concat

普通 Downsample
→ Group-aware Downsample
```

此时必须保证从 Lift Stage 之后：

```text
每个算子都保持群通道语义
```

不能把 `[C,K]` 简单压平成普通 `C*K` 后交给任意卷积，否则通道混合会破坏等变规律。

---

## 3.3 V3：连续 Steerable / E(2)

只有在以下条件满足后才开启：

```text
离散 C12/C24 已证明有收益
角度离散仍是主要瓶颈
算力和实现复杂度可接受
Python 参考模型稳定
C++ 部署方案明确
```

---

# 4. 离散 G-CNN 基础模块

建议新增轻量公共模块，不建立新 Runtime。

```text
libtorch_module/
├─ torch_group_representation.h
├─ torch_cyclic_group_conv.h/.cpp
├─ torch_group_ops.h/.cpp
├─ torch_group_c2f.h/.cpp
├─ torch_equivariant_pose_tower.h/.cpp
├─ torch_angular_extraction_head.h/.cpp
└─ torch_equivariance_losses.h/.cpp
```

---

## 4.1 Group Tensor 布局

统一采用：

```text
[B, C, K, H, W]
```

其中：

```text
B = Batch
C = 每个方向的 Feature Channel
K = 群方向数量
H/W = 空间尺寸
```

禁止在业务层使用模糊的：

```text
[B, C*K, H, W]
```

作为正式合同。

底层为了调用 `conv2d` 可以临时展开，但模块输入输出必须明确恢复为 Group Tensor 语义。

---

## 4.2 Group Lift Conv

作用：

```text
普通图像 [B,3,H,W]
→ 群特征 [B,C,K,H',W']
```

其卷积核由一个基础核通过群旋转生成方向核组。

输出含义：

```text
orientation k
→ 当前区域在第 k 个方向上的响应
```

---

## 4.3 Cyclic Group Conv

输入：

```text
[B,Cin,K,H,W]
```

输出：

```text
[B,Cout,K,H',W']
```

权重共享遵循：

```text
相对方向 h⁻¹g
```

而不是为每个方向独立学习一套无关参数。

实现第一阶段可以使用：

```text
ATen Tensor
旋转后的 Kernel Bank
循环通道 Shift
conv2d
sum / stack
```

在正确性固定后，再根据 Profiling 决定是否写 CUDA Kernel。

---

## 4.4 Group C2f

保留 C2f 的整体结构：

```text
split
→ bottleneck chain
→ concat
→ projection
```

但内部所有 3×3 Conv 替换为：

```text
CyclicGroupConv2d
```

1×1 映射也必须保持 Group 通道排列和方向共享。

---

## 4.5 Group Pooling

提供两种 Pool：

### Orientation-preserving

保留：

```text
[B,C,K,H,W]
```

用于 Angular Head。

### Orientation-invariant

对 K 做：

```text
mean / max / norm
```

得到：

```text
[B,C,H,W]
```

用于继续接入普通分类、Mask 或几何参数 Head。

# 5. Angular Extraction Head

## 5.1 第一版采用 Anchor-Level Angle Distribution

不建议第一版直接在 NMS 后做实例 Mask Pooling。

原因：

```text
NMS 不可微
训练时尚未形成最终实例
Mask Pooling 增加 GT/Prediction Train-Infer Gap
```

当前已有 Task-Aligned Assignment，因此最自然的方式是：

```text
Group Feature P3/P4/P5
→ Angular Head
→ 每个 Anchor 的 K 方向 Logits
```

输出：

```text
P3 angle_logits [B,K,H3,W3]
P4 angle_logits [B,K,H4,W4]
P5 angle_logits [B,K,H5,W5]
```

正样本由当前 `assigned_gt_indices` 与同一个 GT Instance 绑定。

---

## 5.2 Head 结构

每个尺度：

```text
Group Feature [B,C,K,H,W]
        ↓
Shared 1×1 Group Projection
        ↓
Channel Reduction
        ↓
Angle Logits [B,K,H,W]
```

重点是：

```text
沿 K 维保留方向响应
```

而不是把 K 维打散后交给普通 MLP。

---

## 5.3 圆周分布解码

假设第 k 个方向：

```text
φk = 2πk / K
```

概率：

```text
pk = softmax(logits)k
```

对普通 360°有向对象：

```text
z = Σ pk · exp(iφk)
θ = atan2(Im(z), Re(z))
confidence = |z|
```

对 180°对称对象：

```text
z2 = Σ pk · exp(i2φk)
θ = 0.5 · atan2(Im(z2), Re(z2))
```

对 90°对称对象：

```text
z4 = Σ pk · exp(i4φk)
θ = 0.25 · atan2(Im(z4), Re(z4))
```

这样可以正确处理：

```text
Line / OBB / Ellipse：通常 modulo 180°
Square：可能 modulo 90°
Circle：Angle 不可定义
Directed Arc：可能 modulo 360°
```

---

## 5.4 Angle Confidence

至少保存：

```text
resultant_length
entropy
top1_probability
top1_top2_margin
```

不能只返回一个角度值。

建议合同：

```cpp
struct CxAngularEvidence
{
    int group_order = 0;
    int symmetry_order = 1;

    double angle_rad = 0.0;
    double confidence = 0.0;
    double circular_std = 0.0;
    double entropy = 0.0;

    std::vector<float> distribution;

    std::string source_level;
    std::string source_anchor_ref;
};
```

---

## 5.5 亚 Bin 插值

可以使用：

```text
圆周加权均值
局部抛物线插值
Von Mises 分布拟合
```

但不得预先承诺：

```text
15° Bin 一定能获得 <1° 精度
```

应把 `<1°` 作为受控数据上的实验目标，而不是架构天然保证。

---

## 5.6 实例级 Mask Pooling 作为第二阶段

在 Anchor-Level Head 稳定后，再增加：

```text
Group Feature
+
GT / Predicted Instance Mask
        ↓
Differentiable Masked Average Pooling
        ↓
Instance Group Vector [N,C,K]
        ↓
Angular Distribution
```

实现不需要 torchvision ROIAlign：

```text
pooled =
Σ(feature × downsampled_mask)
/
Σ(mask)
```

训练时使用 GT Mask，推理时使用预测 Mask。

该 Head 可作为：

```text
Anchor Angle 的二次校准
```

而不是第一版唯一角度来源。

# 8. 训练 Loss 设计

现有：

```text
L_cls
L_box
L_dfl
L_mask(BCE + Dice)
```

继续保留。

新增：

```text
L_total =
    L_existing
  + λ_group    L_group
  + λ_ang_dist L_angular_distribution
  + λ_ang_vec  L_angular_vector
  + λ_pose     L_pose_consistency
  + λ_calib    L_confidence_calibration
```

---

## 8.1 群等变一致性 Loss

对群元素 `gm`：

```text
x_rot = gm(x)
```

理论目标：

```text
F(gm x)
≈
gm spatial transform
+
group channel cyclic shift
of F(x)
```

定义：

```text
L_group =
‖F(gm x) - ρ(gm)F(x)‖
```

离散 C_N 第一阶段只对：

```text
m × 360° / K
```

进行严格一致性约束。

任意角度增强可用于泛化，但不能作为严格 Group Equivariance Unit Test。

---

## 8.2 Angle Distribution Loss

构建圆周软标签：

```text
qk ∝ exp(κ cos(s(φk - θgt)))
```

其中：

```text
s = symmetry_order
```

Loss：

```text
L_angular_distribution =
KL(q || p)
或
CrossEntropy with circular soft label
```

避免角度在：

```text
0° / 360°
```

处出现不连续。

---

## 8.3 Circular Vector Loss

从分布解码角度后：

```text
L_angular_vector =
1 - cos(s(θpred - θgt))
```

对于 180°对称对象自动使用：

```text
s = 2
```

---

## 8.4 Pose Consistency

利用已有 Mask / Box：

```text
预测 Angle
预测 Width / Height
预测 Mask 主轴
Geometry Target
```

建立一致性约束。

第一阶段只作为弱约束，不应让 Mask 的统计主轴反向主导 Angle Head。

---

## 8.5 Confidence Calibration

目标：

```text
高置信度
→ 角度确实准确

低置信度
→ 系统扩大 FastMatch 搜索范围或回退
```

使用：

```text
Brier Score
NLL
Expected Calibration Error
```

做验证。

# 13. 性能与资源约束

离散 Group Feature 的计算和显存通常随 K 增长。

如果普通通道为：

```text
C
```

不能简单变成：

```text
C × K
```

并保持其他维度不变，否则算力和显存可能迅速增加。

建议采用固定预算：

```text
ordinary channel budget ≈ group_channel × K
```

例如：

```text
普通层 128 channels

C8 Group Layer：
16 fields × 8 orientations

C16 Group Layer：
8 fields × 16 orientations
```

实际预算通过参数量、FLOPs 和延迟统一校准。

第一版必须记录：

```text
parameter_count
activation_bytes
forward_ms
backward_ms
VRAM
```

# 16. CxGeoMetry 中的旋转等变表达

现有 CxGeoMetry 基线要求先把 FastMatch/CxTextInspect 的 C++ 对象网络转换为设备无关的 Tensor 计算图，然后才推进 CPU/CUDA/XPU 分发。

## 16.1 Group-aware Descriptor

当前：

```text
model_descriptor [model_count, D]
```

演化为：

```text
model_descriptor
[model_count, D, K]

observation_descriptor
[observation_count, D, K]
```

K 表示方向响应。

---

## 16.2 Cyclic Correlation

Prototype 匹配不只输出一个 Score，而是：

```text
score_by_angle[k]
```

通过循环相关得到：

```text
best_angle
angle_distribution
angle_confidence
```

这正好可以演化为 CxGeoMetry 自身的：

```text
Distribution Fit
```

与现有 Top-K 和不确定度思想一致。

---

## 16.3 Route 带入姿态

跨层 Route 从：

```text

→ target_node
```

扩展为：

```text
source_node
+ source_orientation
→ target_node
+ target_orientation
```

Route Tensor 可增加：

```text
route_orientation_delta
route_orientation_tolerance
```

使粗层识别到的姿态能够向细层传递。

# 21. 开发约束

1. **G-CNN 是粗姿态模型，不是最终量测模块。**

2. **不得把等变性描述为完全消除所有旋转误差。**

3. **不得承诺 C24 必然达到 1°以内精度。**

4. **Circle 等无唯一角度对象不得强制训练 Angle。**

5. **所有 Angle Loss 必须考虑对象旋转对称性。**

6. **第一版必须保留 YOLOv8-Seg V1，不得原位替换。**

7. **第一版采用并行 Pose Tower，不直接重写整个 Backbone。**

8. **只替换 P3/P4/P5 而未保持前后 Field Type 时，不得宣称严格等变。**

9. **不得直接把 Python e2cnn/escnn 作为生产 LibTorch C++ 依赖。**

10. **当前 Task-Aligned Assignment 和 Dice 已存在，不得重复搭建第二套。**

11. **Geometry Target 必须先改成 per-instance，才能训练 Angular Head。**

12. **Angular Head 必须输出完整圆周分布和置信度，不只输出一个标量。**

13. **G-CNN 输出必须以 `PredictiveHypothesis` 身份进入 FastMatch。**

14. **FastMatch、Normal Trace 和 FormFit 仍拥有最终量测裁决权。**

15. **没有 FastMatch 端到端收益，不得推广到 CxGeoMetry。**

16. **CxGeoMetry 只迁移群表示和方向分布能力，不迁移 YOLO 架构。**

17. **CxGeoMetry 必须先完成 P0 CPU Tensor 等价，再接 Group Ops。**

18. **没有消融实验，不得把 G-CNN 设为默认模型。**

19. **没有 CPU/CUDA 等价，不得宣布设备优化完成。**

20. **没有最终量测精度验证，不得只凭 Angle MAE 宣布方案完成。**

# 23. 最终定义

G-CNN 在整套系统中的最终职责是：

```text
在旋转和干扰条件下
稳定输出：
目标实例
粗中心
粗尺寸
粗角度
角度分布
姿态置信度
```

FastMatch 的最终职责是：

```text
利用粗姿态
缩小搜索范围
提取真实边缘
建立点对应
完成连续几何配准
```

Normal Trace 和 FormFit 的最终职责是：

```text
真实图像边缘证据
几何闭合
拟合残差
量测参数
```

Predictive Geometry Gate 的职责是：

```text
判断结果属于：
DirectMeasurement
ClampedMeasurement
PredictiveHypothesis
Undeterminable
```

CxGeoMetry 后续吸收的是：

```text
旋转等变描述子
方向响应分布
圆周角度解码
群通道 CPU/CUDA 算子
```

而不是吸收整个 YOLOv8-Seg。

**最终原则：模型把姿态预测得更稳定，FastMatch 把搜索和配准做得更高效，Normal Trace 与 FormFit 把量测做得更精确；G-CNN 升级模型感知能力，但不改变五级边界链的精度裁决关系。**
